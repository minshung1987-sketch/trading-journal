# 投資人行事曆：每週排程指示（新對話獨立版）

> 用法：在 claude.ai/code 的 Routines（例行任務）新增排程時，把下面「指示內容」整段貼進去。
> 這份是給「每次開新對話執行」用的，不依賴任何舊對話，Claude 讀完就能獨立完成。

---

## 指示內容（從這行以下整段複製）

任務：每週更新使用者（台灣，繁體中文）的「投資人行事曆」，並直接同步到 GitHub 網站。全程用繁體中文回報。

【省額度原則】只讀需要的部分：用 python / grep 篩選 JSON，不要整份印出 events.json、events_manual.json、news.json 或 index.html；子代理最多 3 個，各給精簡任務；回報精簡。

資料位置：
- 儲存庫 minshung1987-sketch/trading-journal（本排程已綁定，啟動時已 clone，通常在 /home/user/trading-journal；找不到就用 find / -maxdepth 4 -name trading-journal -type d）。開始前 git fetch origin main，git checkout -B main origin/main。
- data/events_manual.json：人工整理的事件（JSON 陣列），本任務只改這個檔。
- data/events.json：網站讀取的檔案＝manual＋自動事件（a:1），不要手寫，一律用 python3 scripts/rebuild.py 重建（會保留「新／改」標記）。
- index.html 內的 TBA 陣列：尚未公布日期的項目。
- 不要修改：scripts/、.github/、news-keys.js、data/news.json（新聞由 GitHub Actions 每小時自動抓）、任何 a:1 事件（台股法說會、股東會、處置股由 GitHub Actions 每天 07:00、19:00 自動更新）。
- 備份頁：Claude Artifact https://claude.ai/artifact/9ZRMLfd4PptRPBYshrd9rn
- 事件欄位：d 日期、e 結束日、c 類別（cb 央行｜eco 總經｜tw 台股法說會｜agm 股東會｜us 美股財報｜tech 科技大會｜ind 產業展會｜disp 處置股｜mkt 交易日程｜pol 政治事件）、t 標題、tm 時間、pl 地點、n 備註、st（o 官方／e 預估）、u 來源網址、k 倒數磚代號、mn 次要、q 自訂新聞搜尋字。改既有事件時不要改標題（標題相同才會被認定為同一事件、顯示「改」標籤）。

要做的事：
1. 重新查證「st 為 e 且日期在未來」的事件是否已正式公告：美股財報（微軟、Meta、亞馬遜、輝達、博通、美光、高通、邁威爾、應材、Palantir、思科、好市多、沃爾瑪、Palo Alto、CrowdStrike、Amgen、Gilead 等）、產業展會預估項目。優先公司投資人網站或新聞稿；找不到官方資料就維持預估。已公告的改成 st:"o"，更新日期、時間（附台灣時間：美國夏令時間到 2026/11/1 結束，之前美東+12、美西+15，之後美東+13、美西+16）與來源網址。
2. 檢查 TBA 清單項目是否已有正式日期，有的話移到 events_manual.json 並從 index.html 的 TBA 刪除。
3. 央行（cb）：未來兩週聯準會官員（主席 Warsh、理事、各區聯儲主席）公開講話（優先 https://www.federalreserve.gov/newsevents/calendar.htm 與各區聯儲網站），IMF／G20／BIS 場合；FOMC、日銀、歐銀決議、紀要、Beige Book 有無變動；FOMC 靜默期（會前第二個週六至會後週四）。新聞轉載的用 st:"e" 並在 n 註明；美東時間換算台灣時間寫入 tm。
4. 總經（eco）：BLS（CPI、PPI、就業、JOLTS）、BEA（GDP、PCE）、Census（零售、耐久財）、ISM 發布日有無變動或補上更晚月份（BLS 網站會擋程式，可用搜尋確認並在 n 註明）。另找新公告的重要大會、投資人日（費半 30 檔與那斯達克前 30 大相關）、新的國外產業展會。
4.5 政治事件（pol）：檢查美國政府預算到期日／停擺風險是否變動、日本是否解散眾議院或公布自民黨總裁選／參議院選舉日期、台灣中選會是否公告 2028 總統與立委選舉日期；有正式日期就從 TBA 移到 events_manual.json（c:"pol"）。
5. 台灣展館：用 WebFetch 或 curl 讀台北世貿檔期表 https://www.twtc.org.tw/exhibition?p=home 與南港展覽館 https://www.tainex.com.tw/event （另讀 ?hall=1、?hall=2），找出未來 90 天內、events_manual.json 還沒有的展會（同展不同名稱也算已有）。只收台股題材：半導體、電子、PCB、AI 伺服器、網通、衛星、能源儲能、機器人、工具機、汽機車、自行車、醫材生技、資安、營建、金融科技、觀光旅遊（旅展→航空、旅行社、飯店類股）；其他消費展（食品、酒、茶咖啡、文創、寵物、家具、婚紗、美容、婦幼、動漫）不收。加入 c:"ind"，d/e 展期，pl 展館與館別，st:"o"，u 用主辦單位官網（展館活動頁上的連結；沒有才用展館頁），n 寫題材與相關族群。
6. 已經過去的事件保留，不要刪除。
7. 有變動才：存檔 events_manual.json → python3 scripts/rebuild.py →（TBA 有變再改 index.html）→ git commit（繁中訊息，結尾加本工作階段規定的歸屬行）→ git fetch origin main && git rebase origin/main（若 data/events.json 衝突：git checkout --theirs data/events.json 後重跑 python3 scripts/rebuild.py、git add、git rebase --continue）→ git push origin main → 比對 git rev-parse HEAD 與 origin/main 確認成功。只推 main，不開 PR。
8. 有變動才重發備份頁：以 index.html 為基礎，把 `<script src="news-keys.js"></script>` 換成內嵌 news-keys.js 內容；把 `fetch("data/events.json"…` 開始到該 `</script>` 前的整段換成 `EVENTS=<events.json 的 events>;NEWS=<news.json 全部>;prep();renderTiles();renderWatch();render();`；「資料載入中…」改成「資料整理於 YYYY/MM/DD（靜態備份版）」；頁尾「本頁每天早上 7 點…」那段換成「此為靜態備份版，資料與相關新聞為整理當下的快照；自動更新版（新聞每小時更新）請看 GitHub Pages 網站。」。先用 Artifact read 讀該網址，再 publish 到同一網址。
9. 回報（精簡）：哪些從預估變官方、哪些新增、哪些變動（分央行、總經、美股、科技大會、產業展會），另立一段「台灣展館新發現」，最後說推送是否成功。沒有任何變動就只說「本週沒有變動」並附一句展館網站讀取狀況，不要推送也不要重發。push 失敗不要重複嘗試（網路錯誤可退避重試 4 次），說明原因與解法，並用 SendUserFile 傳出新的 events_manual.json。

規則：不可憑記憶編造日期；每個新增或變更都要有實際讀過的來源網址；來源是新聞轉載站而非官網時在 n 註明；只能從搜尋摘要確認時也在 n 註明。
